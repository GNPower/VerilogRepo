# IP Cores

This directory contains vendor-generated IP cores and third-party IP for your HDL project.

---

## Purpose

The `ip/` directory stores:

- **Vendor IP Cores** - IP generated by synthesis tools (Vivado IP, Quartus IP, etc.)
- **Third-Party IP** - Commercial or open-source IP cores
- **IP Configuration Files** - `.xci`, `.qsys`, `.qip`, or other vendor-specific formats
- **Generated HDL** - Tool-generated Verilog/VHDL from IP configuration

HOG automatically references this directory when creating and regenerating synthesis projects.

---

## Directory Structure

Organize IP cores by vendor tool or functionality:

```
ip/
├── xilinx/              # Xilinx Vivado IP
│   ├── fifo_gen/        # FIFO Generator IP
│   ├── clk_wiz/         # Clocking Wizard IP
│   └── ila/             # Integrated Logic Analyzer
├── intel/               # Intel Quartus IP
│   ├── pll/             # Phase-Locked Loop
│   └── ram/             # On-chip memory
├── lattice/             # Lattice Diamond IP
└── custom/              # Custom or third-party IP
```

## Vendor IP Types

### Xilinx Vivado IP

Xilinx IP is configured via the IP Catalog and stored as `.xci` files:

**Common Xilinx IP:**
- **Clocking Wizard** - PLLs, MMCMs, clock buffers
- **FIFO Generator** - Synchronous/asynchronous FIFOs
- **Block Memory Generator** - RAM, ROM configurations
- **AXI Interconnect** - AXI4 bus infrastructure
- **ILA (Integrated Logic Analyzer)** - Debug cores
- **VIO (Virtual I/O)** - Runtime signal control

**File Structure:**
```
ip/xilinx/my_fifo/
├── my_fifo.xci          # IP configuration file
├── my_fifo.xml          # IP metadata
└── synth/               # Generated synthesis files (gitignored)
```

**Adding Xilinx IP to HOG:**

1. Generate IP using Vivado IP Catalog
2. Save the `.xci` file to `ip/xilinx/<ip_name>/`
3. Add to HOG project list file (`top/<project>/list/<project>.src`):
   ```
   [lib_name]
   ../../../ip/xilinx/my_fifo/my_fifo.xci
   ```

**Note:** Only commit the `.xci` file. Generated files in `synth/` and component XML are gitignored.

### Intel Quartus IP

Intel/Altera IP uses `.qsys` (Platform Designer) or `.ip` files:

**Common Intel IP:**
- **Avalon Memory-Mapped Components** - RAM, ROM, bridges
- **Avalon Streaming Components** - FIFOs, switches
- **PLL (Phase-Locked Loop)** - Clock generation
- **ALTPLL, ALTDDIO** - Legacy megafunctions

**File Structure:**
```
ip/intel/my_ram/
├── my_ram.qsys          # Qsys/Platform Designer system
├── my_ram.ip            # IP variation file
└── my_ram_inst.v        # Instantiation template
```

**Adding Intel IP to HOG:**

Add to HOG list file:
```
[lib_name]
../../../ip/intel/my_ram/my_ram.qsys
```

## Third-Party and Open-Source IP

### OpenCores IP

[OpenCores](https://opencores.org/) provides free, open-source IP:
- UART controllers
- SPI/I2C interfaces
- Ethernet MACs
- USB controllers
- Video controllers

**Integration:**
```
ip/opencores/
├── uart16550/
├── i2c_master/
└── spi_master/
```

### Custom IP Cores

Store custom-developed reusable IP here:
```
ip/custom/
├── my_dsp_core/
│   ├── rtl/             # IP RTL source
│   ├── doc/             # IP documentation
│   └── sim/             # IP testbenches
```

**Note:** For complex custom IP, consider maintaining a separate repository and adding as a Git submodule.

## HOG Integration

### IP in HOG List Files

HOG references IP cores through list files in `top/<project>/list/`:

**Example `myproj.src`:**
```tcl
# Xilinx IP cores
[my_ip_lib]
../../../ip/xilinx/clk_wiz/clk_wiz.xci
../../../ip/xilinx/fifo_gen/async_fifo.xci

# Intel IP cores
[my_ip_lib]
../../../ip/intel/pll/sys_pll.qsys
```

### IP Regeneration

HOG automatically regenerates IP when:
- The `.xci` or `.qsys` file changes
- The project is created on a new machine
- The tool version changes

## Best Practices

### 1. Version Control

**Do Commit:**
- IP configuration files (`.xci`, `.qsys`, `.ip`)
- IP instantiation templates
- IP documentation

**Don't Commit:**
- Generated synthesis files
- Simulation models (regenerate from config)
- Tool-specific temporary files
- Large binary files

### 2. IP Organization

- **One IP per directory** - Keep each IP core isolated
- **Descriptive names** - Use `<function>_<variant>` naming (e.g., `fifo_async_1024x32`)
- **Document settings** - Include a README or notes about IP configuration
- **Version tracking** - Note the tool version used to create IP

### 3. IP Documentation

For each IP core, document:
- Functional description
- Configuration parameters
- Interface signals
- Timing requirements
- Resource utilization
- Known issues or limitations

**Example IP README:**
```markdown
# Clock Wizard - System Clock Generator

## Configuration
- Input: 100 MHz
- Outputs:
  - clk_out1: 200 MHz (0° phase)
  - clk_out2: 100 MHz (90° phase)
  - clk_out3: 50 MHz (0° phase)

## Resources
- 1x MMCM primitive
- Target Device: xc7z010clg400-1

## Created With
- Vivado 2023.1

## Notes
- Reset is active-high synchronous
- Locked signal indicates all clocks are stable
```

### 4. Simulation

Include IP simulation models:
- Add IP simulation files to `<project>.sim` list
- Use vendor-compiled simulation libraries
- Consider behavioral models for faster simulation

### 5. Cross-Tool Compatibility

If supporting multiple synthesis tools:
```
ip/
├── xilinx/          # Xilinx-specific IP
├── intel/           # Intel-specific IP
└── portable/        # Portable RTL implementations
    └── fifo/        # Vendor-independent FIFO
```

## Common IP Examples

### Example 1: Xilinx Clock Wizard

```
ip/xilinx/clk_wiz_sys/
├── clk_wiz_sys.xci
└── README.md
```

**HOG List Entry:**
```tcl
[work]
../../../ip/xilinx/clk_wiz_sys/clk_wiz_sys.xci
```

**Instantiation (from Vivado template):**
```verilog
clk_wiz_sys clk_gen_inst (
    .clk_in1   (clk_100mhz),
    .clk_out1  (clk_200mhz),
    .clk_out2  (clk_100mhz_90),
    .reset     (reset),
    .locked    (pll_locked)
);
```

### Example 2: Xilinx FIFO Generator

```
ip/xilinx/async_fifo_1k/
├── async_fifo_1k.xci
└── README.md
```

**Configuration:**
- Type: Asynchronous FIFO
- Data Width: 32 bits
- Depth: 1024 entries
- Features: Full/Empty flags, almost-full threshold

### Example 3: Intel ALTPLL

```
ip/intel/sys_pll/
├── sys_pll.qsys
├── sys_pll.v
└── README.md
```

## IP Repositories

### Setting IP Repository Paths

For custom IP repositories, configure in `top/<project>/hog.conf`:

```ini
[main]
IP_REPO_PATHS = ../../../ip/custom ../../../ip/third_party
```

This makes custom IP available in the Vivado IP Catalog.
